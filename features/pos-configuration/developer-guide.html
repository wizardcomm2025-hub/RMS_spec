Feature developer guide

POS Configuration → Tax Setting & Order Channels

The index is README.md; use cases 01–05.

What this feature does

Tax groups and their components, with exactly one default group that every POS bill charges; and the order channels (tables, counters) cashiers pick on the POS.

v1 scope

Tax Setting is fixed end to end: company-checked, permission-checked, atomic save with XML lines, removed components deactivated, a default group, and bills charging only it. Order Channels gets a rebuilt screen only; its API is PosPro's.

How it works end-to-end

Sp_SaveTaxSetting saves a group and its components in one transaction and deactivates components not sent. Sp_SetDefaultTaxSetting swaps the default in one transaction; a filtered unique index allows one default per company. SP_CreateBill and GetTaxDt read only the default group. The Order Channels screen calls the PosPro endpoints on NEXT_PUBLIC_POS_URL with the same payloads as before.

What matters where you sit

Data Tenant DB

Run order matters: the IsDefault column, then the default migration, then the bill procedures — otherwise bills charge no tax. CurrentPercentage is numeric(4,2).

Backend API

Company and user come from the token. Create needs create_tax_setting; edit, status and default need edit_tax_setting. Codes from the procedures map to fixed messages.

Client UI

§12 recipe on both screens; the standard Add / Edit dialog replaces the dark header. Order Channels still uses posAxiosInstance.
