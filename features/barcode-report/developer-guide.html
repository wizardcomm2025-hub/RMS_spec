Feature developer guide

Report → Barcode Report

The index is README.md; the use case is 01-view-barcodes.md.

What this feature does

Stock held under barcodes at the user's locations: one row per item, expanding to each barcode, with status tabs for in stock, expiring soon, expired and used up, a value total, and CSV export.

v1 scope

Real dates, expiry status, one row per item across units, only the user's locations, value from fn_GetItemUnitCost, server paging by item with a real total.

How it works end-to-end

Sp_GetBarcodeStockReport picks the visible barcodes, sets each one's status, applies the tab and filters, computes the unit cost once per item and the totals over everything matched, then returns every barcode of the page's items with the item's figures on each row. SettingController checks view_barcode_report. The page groups rows into items, and calls again per tab for the counts and with no paging for the export.

What matters where you sit

Data Tenant DB

Dates must stay dates: the old procedures returned text, which the browser misread. Barcodes can be in the alternate unit. LocationId can be NULL on legacy rows. New guarded index on item.

Backend API

The result model is keyless on purpose: the old one keyed on the item made a second row repeat the first. Company and user come from the token. totalCount counts items, totalBarcodes counts barcodes.

Client UI

§12 recipe with status tabs. Dates use the company format; money uses Money; below md the row is a card with Show barcodes.
