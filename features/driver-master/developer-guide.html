Driver Master — Developer Guide

Implementation reference for engineers working on Driver Master API, database stored procedures, and Next.js frontend components.

1. Architecture Overview

Driver records belong to tenant companies in dbo.DriverMaster. When dispatches occur, DriverId is recorded against the stock transfer (Sp_SaveTranferandTransferDetails). Therefore, drivers are never hard deleted; instead, status is toggled via IsActive.

2. API Endpoints

4. Key UX Rules

  • Page Header: Displays breadcrumb, title "Driver Master", Refresh icon, About toggle, and "＋ Add Driver". Omits redundant short description.
  • Validation: Live debounced license duplicate check informs user before submission.
  • Confirmations: Deactivating a driver requires explicit confirmation explaining that staff won't be able to select the driver for new transfers.
  • Toast Messages: Accurately reports "Driver created successfully" and "Driver updated successfully" (fixes legacy bug where it announced "Vehicle updated successfully").
