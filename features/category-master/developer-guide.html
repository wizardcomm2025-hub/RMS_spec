Feature developer guide

Setting → Category Master

Plain-language onboarding for engineers picking up work on this feature. The structured index is in README.md; the use-case specs are the NN-<use-case>.md files in this folder. This guide points you at what to read.

What this feature does

Categories group inventory items (for example "Vegetables" under Raw Material) so items, recipes, stock checks and food-cost reports can be organised. Each company has its own categories per inventory type, in two levels: main categories and sub-categories. The screen used to be "Item Category"; in the database it is still StockGroup with ClassificationId = 1 — asset categories live in the same table with ClassificationId = 2 and must never be touched here.

v1 scope

Rename to Category Master, close three cross-company holes (edit, get-by-id and delete didn't filter by company), validate names, codes and the two-level structure on the server, replace delete with an Active / Inactive switch, and rebuild the page on the list recipe. See README.md for decisions and open questions.

How it works end-to-end

The admin dashboard calls POST /Setting/*StockGroup* endpoints with the user's token and the company's Origin. The API takes CompanyId and UserId from the token, forces ClassificationId = 1, checks permissions and calls stored procedures that validate everything under a per-company lock. Inactive categories disappear from item and recipe screens because those already list only active categories.
