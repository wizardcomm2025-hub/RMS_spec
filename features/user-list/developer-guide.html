Feature developer guide

User Management → User List

Plain-language onboarding for engineers picking up work on this feature. The structured index is in README.md; the use-case specs are the NN-<use-case>.md files in this folder. This guide points you at what to read.

What this feature does

Users are the people who sign in to RMS. This screen lists a company's users page by page, adds and edits them, gives them one or more roles and their locations, and switches them on or off. Users are never deleted.

v1 scope

Close the role-assignment hole (anyone could give anyone, themselves included, the Admin role or another company's role), stop password hashes and new passwords reaching the browser, move every rule to the server, protect the last admin and your own account, and rebuild the page on the list recipe with server paging. See README.md.

How it works end-to-end

The page asks /Users/GetUserList for one page at a time (search and status go to the server). The dialog saves in two steps: details through Sp_SaveUser, then roles through Sp_SetUserRoles. Status changes use Sp_SetUserActive. The three procedures share a per-company lock, so the "last active admin" check can't be raced. A role change or a deactivation sets IsForcelogin, so the user must sign in again, and clears their cached permissions.
