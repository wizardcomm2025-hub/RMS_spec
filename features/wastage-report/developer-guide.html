Feature developer guide

Report → Wastage Report

The index is README.md; the use case is 01-view-wastage.md.

What this feature does

What was wasted in a period at the user's locations, why, and what it cost: three views (Entries, By item, By reason), a value total, and CSV export of the current view.

v1 scope

Reason on every row, working export, only the user's locations, main unit, value from fn_GetItemUnitCost, server paging. No charts or period comparison.

How it works end-to-end

Sp_GetWastageHistoryReport filters active entries, converts units, computes the unit cost once per item and the totals over all filtered entries, then returns the page of the chosen view in one shared row shape. SettingController checks view_wastage_report and the dates. The page shows the view, and calls again per type for the tab counts and with no paging for the export.

What matters where you sit

Data Tenant DB

IsActive = 0 means cancelled and must never count. CreatedAt is server local time. New guarded index on location + date.

Backend API

The result model is keyless on purpose: the old model keyed on the item made a second entry repeat the first. Company and user come from the token. totalCount is rows in the view; totalEntries and totalValue are the same in every view.

Client UI

§12 recipe with type tabs and a view toggle inside the card, remembered in localStorage. Dates use the company format; money uses Money.
