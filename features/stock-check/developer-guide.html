Stock → Stock Check

The index is README.md; use cases are the NN-<use-case>.md files.

What this feature does

A physical count per location. Saving a count records a StockCheck row and sets the location's Stock to the counted quantity in the item's main unit; the variance against the system quantity is shown before saving.

v1 scope

Stop "Save Stock" from zeroing uncounted items, always stamp company and user, pick stock rows on the server, convert alternate units, save atomically, allow 0, add server permissions, one-call count sheet with variance, standard page design.

How it works end-to-end

GetStockCheckSheet → Sp_GetStockCheckSheet builds the sheet in one query. SaveStockCounts → Sp_SaveStockCounts validates every line and writes count rows and stock in one transaction under sp_getapplock SCK_<WarehouseId>. The old endpoints are routed through the same save.

Times in UTC, shown in IST (use case 03, 2026-11-18)

Stock Check is the pilot for the platform rule "save with GETUTCDATE(), show in IST". Sp_SaveStockCounts stamps new StockCheck rows in UTC and gives the ledger the IST date. The report and dashboard turn IST days into UTC ranges (−330 minutes). The UI reads the times as UTC with utcToIst() (src/utils/ist-time.ts). Older rows are not converted.
