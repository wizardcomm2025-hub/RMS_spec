Feature developer guide

Super Admin → Company Onboarding

The index is README.md; use cases are the NN-<use-case>.md files.

What this feature does

A super admin onboards a customer in a 4-step wizard: the company, admin user and first location are created in a tenant database, the sub-domain is registered in Central, the plan assigned, and the admin e-mailed a temporary password (changed at first sign-in) with the payment link.

v1 scope

Close the anonymous onboarding endpoint, validate the sub-domain, generate the password server-side, track every onboarding step in Central so failures can be retried, create the first location, e-mail the payment link, force a password change at first login.

How it works end-to-end

CompanyOnboard writes a CompanyOnboarding row, then runs the steps Company (tenant usp_CompanyOnboard_Save, one transaction) → Register (SiteRegistry) → Plan (AssignCompanySubscription) → Email → Payment, saving progress after each. RetryOnboarding resumes from the failed step. Sign-in returns mustChangePassword; the app routes to /set-password until it is cleared.
